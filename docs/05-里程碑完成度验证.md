## 2. 验证方法：按阶段标记切

只认代码里作者自己写的标记，切点落在作者声明的段落边界上：

- Python：`# ====== 统一任务池 (M1) ======`、`# M4: 撤销完成 = 撤销打卡`
- JS：`// ====== 晚间小结 (M3 日结) ======`
- HTML：`<!-- ====== 周计划 (M5) ====== -->`

识别规则刻意收紧，避免把 `MiniMax-M3` 这类模型名误判成里程碑 M3：标记要么出现在注释正文**开头**（`# M4: ...`），要么被**圆括号包住**（`(M3 日结)`）。于是 `# 注意: M3 不支持 OpenAI ...` 与 `(prompt 软约束对 M3 不够)` 都不会被误判。

切点再分三档：

| 档位 | 含义 | 是否算问题 |
|---|---|---|
| **安全** | 不在任何多行 token 内部，两侧都是完整语句 | 否 |
| **片段** | 落在容器字面量内部（dict/list/调用参数），代码没坏但单独抽出来不是完整单元 | 否，列出供人眼确认 |
| **危险** | 落在多行字符串/模板串内部，切开会真的把代码劈坏 | **是** |

判定实现：Python 用标准库 `tokenize`（能算准括号深度、识别跨行 token）；JS 用自写扫描器（跟踪字符串/模板串/注释状态与括号栈）；JS 顶层段落再单独交给 `node --check` 独立解析，确保每个里程碑的整段代码本身就是合法 JS。

## 5. 验证器自检（negative control）

"全部安全"不能只是一句没人验证过的断言。`scripts/verify_milestones.py --self-test` 用 6 个人造切点验证检测器本身有效：

```
  ✓ py-危险      期望=危险   实得=危险   (标记落在多行字符串内部)
  ✓ py-片段      期望=片段   实得=片段   (标记落在多行调用参数内部)
  ✓ py-安全      期望=安全   实得=安全   (标记在语句级)
  ✓ js-危险      期望=危险   实得=危险   (标记落在模板字符串内部)
  ✓ js-片段      期望=片段   实得=片段   (标记落在多行调用参数内部)
  ✓ js-安全      期望=安全   实得=安全   (标记在顶层语句级)
```

第一轮写完时 `py-危险` 是**失败**的（跨 token 检测条件写反，把落在三引号串里的标记判成了安全）。自检把它抓出来后已修正——这也是为什么自检必须存在。
