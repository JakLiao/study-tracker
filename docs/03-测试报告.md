### §3.2 [本测试新发现] 代理凭据轮换导致 server 进程反复需重启（环境问题, 非代码 bug）

| 字段 | 内容 |
|---|---|
| **位置** | OpenClaw 平台代理凭据轮换机制（每 1-2 分钟）→ server 进程持有的 HTTPS_PROXY 凭据过期 → `call_minimax()` 返 `AI_NETWORK` (ProxyError) |
| **现象** | 测试启动后 30s-2min 内, 第一次 `POST /api/parse` 实打 AI 时大概率返 `HTTP 200 {"ok":false,"error":{"code":"AI_NETWORK","message":"AI 请求失败: ProxyError","items":[]}}` |
| **影响** | **修真已通过结构化错误 + 重试 + 前端降级 UI 接住**, 测试或用户使用层面**无实际失败**, 只是在测试自动化时需要频繁重启 server |
| **修真前/后对比** | 修真前无此问题（修真的 verify-report §2.4 已详述, 是已知环境特性）· 修真后**修真代码路径反而让此问题对用户透明化**（HTTP 200 + 结构化错误 + 前端降级, 修真前会抛 5xx） |
| **测试自动化层面影响** | 跑 `tests/e2e/test_e2e_endpoints.py` 直跑 5 次中前 3 次因 AI_NETWORK 卡在 section 3, 第 4 次成功跑完 sections 1-5 后在 section 6 撞 P1 bug crash — **测试脚本本身需要"重启 server + 重跑"才能跑通 AI 真打部分**（修真已固化此模式到 `/tmp/restart_and_e2e.sh`） |
| **建议** | **不修真**, 这不是代码 bug — 是 OpenClaw 平台代理凭据轮换机制 + 修真后结构化错误正确接住的副产物。后续若要 CI 化测试, 可在 CI runner 里 `set -a && . ~/.bashrc && set +a && python3 -m uvicorn ... &` + 监控 server stderr 日志 + 周期性重启拿新凭据 |
