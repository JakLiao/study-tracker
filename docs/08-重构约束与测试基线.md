## 0. 总策略：加法，不是重写

现有测试把**家长端**的 DOM 结构与 CSS 规则钉得很死。因此本次改造采用：

| 层 | 做法 |
|---|---|
| CSS | **不动**既有选择器的结构语义；改**令牌值**，在 `[data-role="parent"]` / `[data-role="kid"]` 下重新定义；新增组件用新类名 |
| JS | **保留** `boardHint()` / `hintBlock()` / `optionalGroupOpen()` / `subjectTimeStats()` / `renderAssignment()` 等既有函数的签名与产出；新增 `renderKid*` / `renderParent*` 分支 |
| HTML | 保留既有 `<symbol>` 图标定义与 `id`；新增图标用新 symbol |

**一句话**：家长端的"骨架"不动，只换"皮"；孩子端是**全新的一层**，用新类名承载。

## 2.5 禁止外部 CDN 依赖（**硬红线**）

`tests/test_datepicker.py::test_no_cdn_dependency` 钉死「页面不得直接引用外部 CDN」。
这条约束在本次改造里被扩展为**字体也不许走 CDN**：

> 规范 §3 初稿写的是引 Google Fonts（`Kaisei Decol` 楷体 + `Noto Serif SC` 宋体），
> **已废弃**。项目有「离线可用」的硬约束，Google Fonts 走 CDN 时离线环境拿不到字体，
> 会整页退回浏览器默认字体 —— 角色区分（楷体=孩子端 / 宋体=家长端）就丢了。
>
> 改用**系统自带**字体：楷体 `KaiTi, Kaiti SC, STKaiti`，宋体 `SimSun, Songti SC, STSong`。
> Windows / macOS 都自带，离线可用，且角色区分照旧。

| 角色 | font-family |
|---|---|
| 家长端 | `"Songti SC", "SimSun", "STSong", serif` |
| 孩子端 | `"KaiTi", "Kaiti SC", "STKaiti", "Kaiti TC", cursive` |
| 数字 | 一律系统黑体 + `tabular-nums`，**不跟随**角色字体 |

`tests/test_header_ui.py::test_role_fonts_are_system_fonts` 现在断言「无 CDN 引用」。

**图表库同理（2026-11-02）**：Apache ECharts 5.5.1 **本地 vendor** 到
`app/static/vendor/echarts.min.js`（1,030,855 bytes，Apache-2.0）。
来源与校验值记在 `app/static/vendor/README.md`。
`tests/test_chart_vendor.py` 钉住：文件存在、不是 CDN 引用、sha256 与记录一致、
`index.html` 的脚本顺序是 `echarts → charts.js → dual.js → app.js`。

> 顺带一条实测：`app/static/vendor/README.md` 里原先记的 flatpickr 升级源是
> jsdelivr，**实测不可达（HTTP 000）**；改成 unpkg 后可达（200）。

## 2.6 对比度复核表（改动色值必须重算）

**主色对白底、且对自身浅底 chip 都必须 ≥ 4.5:1（WCAG AA）**。
浅底 chip 上是主色字，实底 chip 上是白字 —— 两头都得够，改一个色值要同时验两列。

| 类别 | 主色 | 浅底 | 主色/白底 | 主色/浅底 |
|---|---|---|---|---|
| 语文 | `--s-yu-c: #BF3B2E` | `--s-yu-t: #FBEAE6` | 5.41 | 4.64 |
| 数学 | `--s-shu-c: #2C6BA8` | `--s-shu-t: #E7F0F8` | 5.56 | 4.82 |
| 英语 | `--s-ying-c: #457315` | `--s-ying-t: #F0F5E4` | 5.65 | 5.08 |
| 培训 | `--s-pei-c: #6B4C9A` | `--s-pei-t: #EEEAF6` | 6.72 | 5.67 |
| 习惯 | `--s-xi-c: #1F7368` | `--s-xi-t: #E4F1EF` | 5.66 | 4.89 |
| 待做 | `--st-todo-c: #6E6459` | `--st-todo-t: #F0EDE8` | 5.78 | 4.95 |
| 进行中 | `--st-doing-c: #8F5600` | `--st-doing-t: #FBF0DC` | 6.00 | 5.32 |
| 已完成 | `--st-done-c: #1D7A4C` | `--st-done-t: #E3F2EA` | 5.33 | 4.61 |

## 5. 常见坑

| 坑 | 说明 |
|---|---|
| CSS 特异性打架 | 新组件类名一律**不复用**旧类名（`.kid-card` 不要继承 `.card` 的 padding）；要用 `@layer` 或更靠后的位置保证覆盖顺序 |
| 令牌被旧规则写死 | 既有样式里若有 `#FFF8F0` 这类**字面色值**，角色切换后不会跟着变 —— 新增角色块时优先用 `var()` |
| `data-role` 没落到 `<html>` | 角色状态必须在 `<html>` 上（`document.documentElement.dataset.role`），否则首帧闪一下旧皮肤 |
| 星星位置随机 | 星星位置用**固定种子**派生，不能用 `Math.random()`，否则重绘时星星乱跳 |
| 庆祝层不认 reduced-motion | `prefers-reduced-motion: reduce` 时只留静态文案 |
| 数字字体 | 数字**一律**用系统黑体 + `tabular-nums`，不跟随楷体/宋体，否则竖列对不齐 |
| 既有 `boardHint` 被顺手改 | 家长端提示语有 node 回归脚本逐字钉着，别碰 |
| **`dual.js` 排在 `app.js` 之后** | `app.js` 启动时就会 `switchTab()` → `loadReview()`，靠 `typeof renderKidReport === 'function'` 判断孩子端渲染器在不在。dual.js 排在后面 → 那一刻还没下载执行 → 孩子端复盘页整段渲染出家长的周报和偏差表。**dual.js 必须前置**；app.js 侧另有 `'dual-ready'` 事件兜底 |
| **新组件漏了 CSS** | `.cal-tip`（日历悬停详情卡）初版只在 JS 里建了 DOM，**CSS 里一条规则都没有** —— 卡片以裸文本流在文档末尾，家长根本看不见。DOM 里有 ≠ 界面上有，**每个新组件类都要在 `styles.css` 里落一条规则**，且要截图确认 |
| **`hashchange` + `popstate` 双绑定** | 同一次导航浏览器会**连着发两个事件**，都绑在 `applyHashRoute` 上就会把当前页渲染两遍（复盘页并排出现两份周报，孩子端出现两个 `.kid-report`，接口也多打一倍）。用 `_lastRoutedHash` / `_lastRoutedTab` 去重 |
| **绝对定位 vs 视口坐标** | `getBoundingClientRect()` 是**视口**坐标，浮层要用 `position: fixed`；用 `absolute` 就得再补 `scrollY`，页面一滚就错位 |
| **接口字段名对不上** | 周计划的课外班字段是 `project_name` / `start_time` / `end_time`，写成 `s.name` 取不到值，会全部落到占位词上（曾显示成「课外班：课」） |
| **条件奖励要能回收** | `bonus_all_done`（全勤 +3 星）是**条件奖**：撤销一条完成后当天就不再全勤，那 3 颗星必须一起删掉，否则孩子白拿 |
| **孩子端卡片别堆成「大卡片」** | 2026-11-01 用户反馈：「项目占用位置太高了，看起来像是待办事项」。初版任务卡把学科行 / 任务名 / 按钮行竖着堆三行，一张 138px，一屏两三项 —— 孩子没法一眼数出还剩几件事。压成**单行**（任务名 + 右侧操作）后 66px，一屏五六项。触控目标不缩水：「完成」仍 48px，计时器改 48×48 图标 |
| **并发 pytest 互踩** | 多个 pytest 进程共用 `study_tracker_test` 会互相 TRUNCATE + 抢 `schema_meta` 锁，表现为随机 Deadlock / FK violation。**每个并发进程用各自的 `TEST_DATABASE_URL`**（`database_url_with_name(DATABASE_URL, 'xxx')`） |

### 5.1 接 ECharts 时踩的坑（2026-11-02 新增）

| 坑 | 说明 |
|---|---|
| **画布不认 CSS 变量** | `itemStyle: { color: 'var(--c-语)' }` 在 canvas 上**画不出来**（画布只认具体色值）。必须运行时用 `resolveCssColor()` 把 `var(--x)` 解析成实际色值 |
| **`resolveCssColor` 的正则要用中文变量名** | 变量名是 `--c-语` / `--c-数` / `--c-英` —— 用 `\w` 匹配**匹配不到**（`\w` 只认 ASCII 字母数字下划线），会静默落回 ECharts 默认调色板，所有科目色全错。正确写法：`/^var\(\s*(--[^\s,)]+)\s*\)$/` |
| **同一 DOM 二次 init 会警告** | ECharts 对同一个容器 `init()` 两次会警告 "There is a chart instance already initialized"。切周期前必须 `disposeCharts(ChartRegistry)` —— 只 `innerHTML=''` 摘 DOM **不 dispose**，canvas 与 resize 监听都留着，切十次泄漏十个实例 |
| **没有 canvas 不能建图** | jsdom 没装 canvas 包时 `getContext('2d')` 返回 null，`echarts.init()` 直接抛 "Can't get context from the given item"。必须先 `canRenderCharts()` 探测，拿不到就**降级成 HTML 表格**，不白屏 |
| **容器必须有确定高度** | ECharts 按容器实际像素算布局，容器高度为 0 → 画出来是空白。`.wt-chart-canvas` 写死 `height: 260px` |
| **脚本顺序** | `echarts.min.js` → `charts.js` → `dual.js` → `app.js`。`app.js` 末尾的 `switchTab()` 在**加载期**就会触发 `loadReview()`，所以 `charts.js` 必须先于 `app.js` 就位 |
| **`window.eval()` 里顶层函数声明不泄漏** | jsdom 的 `w.eval(code)` 里，`'use strict'` 的脚本顶层函数声明**不会**成为 `window` 的属性（实测 `strictFn: undefined` / `sloppyFn: function`）。所以：**`charts.js` 不能加 `'use strict'`**（否则 `app.js` 调 `buildDailyTimeNote` 会 ReferenceError）；而 `app.js` 本身就是 strict 的，测试 harness 要在**同一个 eval** 里追加 `globalThis.__fn = fn;` 才能取到它的函数 |
| **角标不能压在柱身上** | markPoint 默认 `symbolSize: 9` 装不下三位数，文字会溢出并盖住最上面那一段的段内数字（实测「190」压在「40」上）。改成**白底红字 + 红框的标签**放在柱顶**上方**（`position: 'top'`），并给 `grid.top` 多留一条空白 |
