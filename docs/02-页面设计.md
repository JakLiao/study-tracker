## 0. 这一版改了什么

v1 的基调是「**一份给家长看的家长会备忘录**」，并且明确写着
「不卡通、不儿童化、不游戏化」「禁止任何『祝贺你完成作业』式的弹窗」。

这套判断在**只服务家长**时是对的。问题在于真实场景里坐在平板前的是**孩子**，
而家长要的是效率与结论——**两个诉求被压进一套界面，两边都不好用**：

- 孩子看到的是「已收尾 / 必做收尾 / 选做 / 过载 / 冲突天数」这类内部语言，
  操作是 5 个并排按钮，完成后只有一行文字提示
- 家长看到的是低饱和米棕 + 极简扁平，扫读时重点抓不住，
  也没有批量管理入口，只能逐条点

v2 的核心判断：**放弃「一套界面通吃双用户」**。

| | 孩子端 | 家长端 |
|---|---|---|
| 纸 | **方格纸**（小学生真正的作业本） | **横线账本**（备课本） |
| 密度 | 低。一屏只放「今天要做什么」 | 高。一屏放得下全局 |
| 语言 | 「还差 2 项就完成啦」 | 「本周用时 520 分，比上周少 245 分」 |
| 操作 | 一个大「完成」按钮，其余收进 ⋯ | 全量操作 + 批量勾选 |
| 情绪 | 星星、贴纸、庆祝 | 无装饰，只有结论 |
| 底色 | 蜡笔黄 `#FFC53D` | 深靛蓝 `#1D4E7C` |

但两端**共用同一套学科色与状态色编码**——家长和孩子看的是同一个东西的两头，
颜色含义不能各说各话。

## 1. 设计原则

| # | 原则 | 怎么落地 |
|---|---|---|
| P1 | **角色分层，不是换皮** | 切角色换的不只是颜色，还有信息密度、术语、操作数量、页面模块 |
| P2 | **孩子端做减法** | 减信息、减操作、加趣味、加激励。首屏只留「今日任务 + 进度」 |
| P3 | **家长端做加法** | 加数据价值、加管理效率、加规划工具。每个数字都要有直白结论 |
| P4 | **一套颜色编码贯穿全站** | 学科色 / 状态色在看板、日历、复盘、图表里含义完全一致 |
| P5 | **时长是英雄元素** | 预估 / 实际分钟数一眼可读，数字齐（`tabular-nums`） |
| P6 | **所有操作可逆、可追溯** | 每个数据点都能点回 `source_span` 原文；完成可撤销，星星同步退回 |
| P7 | **空状态 / 失败状态也是产品** | 不能只有「成功」长得好 |
| P8 | **颜色不是唯一信息载体** | 状态一律「形状 + 颜色 + 文字」三重信号 |

### 1.1 明确不做

- ❌ 孩子端的**管理性**信息：晚间小结、截止提醒、置信度徽章、学科用时统计
- ❌ 孩子端的**成人术语**：收尾 / 必做收尾 / 过载 / 冲突天数 / 复盘
- ❌ 家长端的**情感化装饰**：贴纸、吉祥物动画、庆祝弹窗
- ❌ 两种模式共用的**字号体系**：孩子端任务名更大、触控目标 ≥48px
- ❌ 渐变背景、毛玻璃、霓虹色
- ❌ Emoji 作为视觉装饰（仅作为文字前缀，且孩子端也不加）
- ❌ 微动效超过 260ms

## 2. 色彩系统

### 2.1 学科色（两角色共用，贯穿看板 / 日历 / 复盘 / 图表）

主色对白底对比度均 ≥ 4.5:1。

| 科目 | 主色 | 浅底 | 选色理由 |
|---|---|---|---|
| **语文** | `#BF3B2E` 朱砂 | `#FBEAE6` | 偏赭的暖红，避开扎眼正红 |
| **数学** | `#2C6BA8` 靛青 | `#E7F0F8` | 沉稳蓝，与语文暖色拉开距离 |
| **英语** | `#457315` 草绿 | `#F0F5E4` | 偏黄的绿，和「完成」状态的蓝绿区分 |
| **培训** | `#6B4C9A` 紫 | `#EEEAF6` | 培训没有科目，用紫表示来源 |
| **习惯** | `#1F7368` 青 | `#E4F1EF` | 习惯任务用青，与培训区分 |

### 2.2 状态色

| 状态 | 主色 | 浅底 | 形状信号 |
|---|---|---|---|
| 待做 | `#6E6459` | `#F0EDE8` | 空心圆点 |
| 进行中 | `#8F5600` | `#FBF0DC` | 实心圆 + 进度条 |
| 已完成 | `#1D7A4C` | `#E3F2EA` | 对勾 + 花贴纸 |
| 选做 | `#6F6A5F` | `#F2F0EC` | 虚线描边 + 「选」字 |
| 已逾期 | `#C2321F` | `#FBE7E3` | 左侧红条 + ⚠ |

**关键规则**：「进行中」是唯一用实心填充的状态；「已完成」的绿色与「英语」的草绿
刻意选了不同色相（145° vs 100°），避免在混排页面里串读。

### 2.3 角色 chrome

**家长端**：白纸 `#FFFFFF` / 墨黑 `#16130F` / 深靛蓝 `#1D4E7C` / 横线账本底纹。

**孩子端**：作业本纸 `#FFFBF2` / 墨黑 `#2B2622`（不用纯黑，护眼）/ 蜡笔黄 `#FFC53D` / 方格纸底纹。

完整令牌表见 `docs/07-双角色改造规范.md` §2。

## 3. 字体与字号

### 3.1 字体分工（这一版的重点）

| 角色 | 用途 | 字体 | 为什么 |
|---|---|---|---|
| 孩子端 | 标题 / 任务名 | **系统楷体** | 小学生练的就是楷体。用孩子正在学的那套字排他要做的事，认字成本直接降一档 |
| 家长端 | 标题 | **系统宋体** | 宋体是「备课本 / 批改记录」的气质，不是消费级 App 的气质 |
| 两端 | 正文 / UI | 系统黑体 | PingFang / 雅黑，最快 |
| 两端 | **所有数字** | 系统黑体 + `tabular-nums` | **不用**楷体宋体渲染数字，否则竖列对不齐 |

**刻意不引 Google Fonts CDN。** 本项目本地部署、要求离线可用
（`tests/test_datepicker.py::test_no_cdn_dependency` 钉着「页面不得直接引用外部 CDN」），
而楷体与宋体 Windows（`KaiTi` / `SimSun`）与 macOS（`Kaiti SC` / `Songti SC`）都自带。
用系统字体：保住角色区分、不引入网络依赖、不用下 20MB 的中文字库、离线也不会闪一下。
字体栈在 `styles.css` 的 `--font-display`（按 `[data-role]` 覆盖）。

### 3.2 字号层级

| 层级 | 字号 | 字重 | 用途 |
|---|---|---|---|
| Hero | 34px | 700 | 家长端完成率大数字 |
| H1 | 22px | 700 | 页面标题 |
| H2 | 17px | 700 | 区块标题 |
| Body | 15px（孩子端 17px） | 400 | 任务名 |
| Body-s | 13px | 400 | 副信息 |
| Caption | 12px | 400 | 辅助说明 |
| Number | 18px | 700 | 分钟数 / 星星数 |

**硬约束**：所有数字 `font-variant-numeric: tabular-nums`；数字字号 ≥ 14px；
卡片之间的数字纵向 baseline 对齐。

## 4. 组件规范

### 4.1 孩子端 · 星星罐（**签名组件**）

这是整个孩子端最值得记住的东西，也是**替换**「进度条百分比」的理由：
百分比是**评价**（「你完成了 67%」），星星罐是**收集**（「你攒了 18 颗」）。
小孩对收集的感知远强于对百分比的感知。

```
┌─────────────────────────────────────┐
│   ╭───╮        还差 2 项就全部完成啦 │
│   │ ★★│        今天拿到 3 颗星        │
│   │ ★★│★       罐里有 18 颗           │
│   ╰───╯                              │
└─────────────────────────────────────┘
```

- 玻璃罐是内联 SVG；星星从罐底往上堆，最多可见 9 颗，超出显示 `+N`
- 星星三色取 `--star` / `--star-2` / `--star-3`，但**位置由固定种子派生**，
  绝不用 `Math.random()`——否则每次重绘星星乱跳，孩子会以为坏了
- 全部完成时罐子加 `.is-full`，星星溢出罐口

### 4.2 孩子端 · 任务卡

```
┌─────────────────────────────────────┐
│ ▎语文              约 20 分钟   ⋯   │
│   完成知能 P14                       │
│   ┌───────────────┐                  │
│   │    完 成      │                  │
│   └───────────────┘                  │
└─────────────────────────────────────┘
```

- 圆角 20px，底 `#FFF6E4`，描边 `#EADFC8`
- **只保留一个「完成」大按钮**（48px 高，蜡笔黄 + 墨字）。编辑 / 今天不做 / 删除
  全部收进右上角 ⋯ 菜单——低龄儿童最容易误点，这一层要挡住
- 完成后：左色条转绿、卡片降饱和、显示「完成啦 ✓」

### 4.3 家长端 · 批改台

```
┌──────────────────────────────────────────┐
│ 完成率        剩余用时       学科分布      │
│  67%           38 分        ▰▰▱           │
│ 4/6 项        还要写多久   语 60% 数 40%   │
├──────────────────────────────────────────┤
│ ☐ 全选  已选 3 项  [设为选做][改期][删除]  │
├──────────────────────────────────────────┤
│ ☐ ▎语文  完成知能P14          20分  待做 ⋯│
└──────────────────────────────────────────┘
```

- 数据卡下方一句**直白结论**：「今天比平时少 20 分钟，效率不错」——
  家长不该需要自己解读数字
- 「删除」在批量条里是红色描边的危险样式，且**必须二次确认**

### 4.4 孩子端 · 贴纸册日历

每格一张贴纸位：全完成 → 学科色星形贴纸；部分完成 → 半张；无作业 → 留白。
今天那格有一圈手绘感虚线框。

家长端同一个位置是热力图 + 悬停详情卡（完成率、各学科用时、课外班安排）。
**两种视图是同一个日历的两种读法**，不是两个页面。

### 4.5 孩子端 · 成绩单

本周完成率横幅 + 勋章墙（未获得是浅色轮廓 + 锁）+ 星星明细。
勋章用**内联 SVG 图形**，不用 emoji。

## 5. 页面详细设计

### 5.1 今日页（`#/board`）

**孩子端**（从上到下）：

1. 顶栏：日期 + 角色切换
2. 星星罐 hero：罐子 + 鼓励语（按剩余项数分档）
3. 任务卡列表：按优先级排序，首屏最多 3~4 项
4. 「有空再做」分组
5. 底部 Tab

**不出现**：晚间小结、逾期提醒、未来 7 天到期、学科用时统计、置信度徽章。

**家长端**（从上到下）：

1. 顶栏：日期 + 直白结论 + 角色切换 + 头像菜单（设置）
2. 3 张数据卡：完成率 / 剩余用时 / 学科分布
3. 截止提醒 + 逾期提醒（异常提示，插在概览后）
4. 批量操作条（选中时出现）
5. 密集任务行列表（待完成 / 已收尾）
6. 晚间小结（页面底部，每日收尾的可选动作）

### 5.2 登记页（`#/entry`，家长端专属）

保持 v1 结构：大文本域 → 解析 → 逐条确认表格 → 入库。
「手动添加」按钮**始终可见**，不依赖 AI 状态。

### 5.3 日历页（`#/list`）

- 家长端：完成情况 / 用时热力图（两个既有模式保留）+ 悬停详情卡
- 孩子端：贴纸册（新增第三个模式）
- 默认模式按角色不同：家长 = 完成情况，孩子 = 贴纸册

### 5.4 周计划页（`#/week`，家长端专属）

保持 v1 的两步流程。入口从日历页右上角进，不占 Tab 位。

### 5.5 复盘页（`#/review`）

- 家长端：周期选择 + 环形占比图 + 每日用时折线 + 薄弱项分析 + 未完成任务「挪到下周」
- 孩子端：成长成绩单（完成率横幅 + 勋章墙 + 星星明细）

### 5.6 设置页（`#/settings`，家长端专属）

分组列表：基本信息 / 单科基线预估 / 任务类型基线 / 作息 /
**家长端 PIN** / **护眼模式** / 解析模型 / **数据与隐私** / 数据导出。

「作业数据保存在本机，不上传到任何服务器」这行从首页 footer 移到这里。

## 6. 护眼模式

针对小学生晚间写作业场景：降低蓝光、略降对比度、纸色更暖。
**只作用于孩子端**（家长端是白天办公场景，不需要）。设置页开关，状态存本地。

实现：`[data-role="kid"][data-eyecare="on"] body { filter: sepia(.2) hue-rotate(-8deg) saturate(.88) brightness(.97) }`

## 7. 文案口径

### 7.1 孩子端（禁止成人术语）

| 家长端 | 孩子端 |
|---|---|
| 已收尾 | 已完成 |
| 必做 | 必须完成 |
| 选做 | 有空再做 |
| 已逾期 | 逾期啦 |
| 复盘 | 成绩单 |
| 训练打卡 | 练习打卡 |
| 预计用时 | 约 X 分钟 |

鼓励语按剩余项数分档：0 项「今天的作业全部完成啦！」/ 1~2 项「还差 N 项就全部完成啦」/
3~5 项「今天作业有点多哦，慢慢来」/ ≥6 项「今天有点多，先做最想先做的那项」。

### 7.2 家长端

保留专业术语，但**每个数据都补一句直白结论**：

> 本周作业用时 520 分钟，比上周少 245 分钟，效率提升了。

### 7.3 一个动作从按钮到提示，名字保持一致

「设为选做」按钮点了之后 Toast 就说「已设为选做」，不换词。

## 8. 响应式断点

| 断点 | 宽度 | 布局 |
|---|---|---|
| 默认 | < 640px | 单列、卡片满宽、底部 Tab 固定 |
| Tablet | ≥ 640px | 单列居中 max-width 560px、Tab 顶置 |
| Desktop | ≥ 1024px | 居中 max-width 720px、可选双栏 |

底部 Tab 高度 56px + 安全区。当前页实心填充 + 高对比色，其他灰字 + 图标。
**每个角色 3 个 Tab**，不出现 5 个以上。

## 9. 给实现的 5 个坑（必须看）

### 坑 1：数字必须 `tabular-nums`

预估 35 分 / 实际 40 分上下排列时，普通字体数字宽度不等，竖列对不齐，家长扫读极费劲。
全局 `font-variant-numeric: tabular-nums`，**并且数字不要用楷体/宋体渲染**。

### 坑 2：孩子端首屏只有「今天要做什么」

孩子端首屏**不允许**出现晚间小结、截止提醒、置信度徽章、学科用时条。
这些是家长要的信息，放在孩子端只会挤掉任务列表——而孩子端的任务列表**就是全部**。

### 坑 3：完成反馈要分层

- 单项完成：孩子端星星飞进罐子（260ms），家长端行内变绿无动效
- 全部完成：孩子端全屏庆祝层；家长端**不弹**（弹了就变成噪音）
- 撤销完成：星星退回，无庆祝

`prefers-reduced-motion: reduce` 下全部动效关闭，只留静态文案。

### 坑 4：星星位置不能用随机数

每次重绘星星位置都变，孩子会以为页面坏了。用固定种子从 id 派生位置。

### 坑 5：角色状态必须在首帧前落到 `<html>`

`data-role` 设晚了，用户会看到一闪而过的旧皮肤。在 `<head>` 里用一段内联脚本
读 `localStorage` 直接设 `document.documentElement.dataset.role`。

## 10. 无障碍（A11y）

- 全部交互元素键盘可达，`:focus-visible` 有 2px 描边
- 状态按钮、置信度徽章加 `aria-label`
- 颜色不是唯一信息载体：状态除颜色外还配 shape + 文字
- 触控目标：孩子端 ≥48×48px，家长端 ≥44×44px
- 不依赖 hover 显示关键信息（移动端无 hover）——日历悬停详情卡在移动端要点开
- 贴纸 / 勋章 / 星星罐的 `<svg>` 必须 `aria-hidden="true"` + 相邻 `aria-label` 文字

## 11. 与旧版的关系

v1 文档里「家长视角、不是孩子视角」那套原则（P1）与本文**直接冲突**，
以本文为准。v1 中仍有价值的技术细节（`tabular-nums`、完成时补填用时的中性话术、
低置信度必须显眼、「手动添加」按钮始终可见）**继续有效**，
已在 `docs/08-重构约束与测试基线.md` 里固化成测试断言。
