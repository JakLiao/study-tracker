# 小学生作业跟踪 · 用户流程与视觉改版设计

日期：2026-09-28
状态：已与用户确认，待实现

## 一、背景与目标

家长每天的真实流程是四步：

1. 解析老师发的语数英作业通知
2. 把作业归到正确的日期
3. 看今天还有哪些没做
4. 结束一项作业——但**不只有"完成"一种方式**

第 4 点是本次改版的出发点。现有实现把"选做"和"跳过"混为一谈，且数据层早已具备能力、前端却完全没接。

同时现有配色为冷灰基调（`#F5F6F8` 底 + 近黑文字 + 低饱和砖红/灰蓝/灰绿），与"适合小学生的明亮可爱风"要求相悖，整体换掉。

## 二、已确认的产品决策

| # | 决策 | 说明 |
|---|---|---|
| 1 | **选做与跳过是两个独立概念** | 选做 = 作业本身的属性（`is_optional`）；跳过 = 家长对本次的决定（`status='skipped'`）。两者都要能在看板上**来回切换**。 |
| 2 | **进度口径：跳过算已收尾，不当完成** | 进度 = (done + skipped) / (total − optional)。跳过后进度条可走到 100%，但"完成"计数不增加。 |
| 3 | **录入：批次级默认日期 + 每行可改** | 解析页顶部一个归属日输入框（默认今天），AI 识别出日期的行自动填自己的，识别不出的**留空并标红**，不再静默猜今天。 |
| 4 | **配色：奶油糖果 + 科目标签实底色** | 见 §四。 |
| 5 | **看板分区：待完成 / 已收尾 / 选做（折叠）** | 顶部先回答"今天还剩什么"，再看细节。 |

不采纳：部分完成态（用户明确不需要）。

## 三、功能设计

### 3.1 状态模型

保持现有四态 `todo / doing / done / skipped`，不新增枚举。看板上呈现为三个动作：

| 动作 | 映射 | 行为 |
|---|---|---|
| 开始 | `todo → doing` | 单向推进，立即 PATCH |
| 完成 | `doing/todo → done` | 收尾。若未填实耗则弹出补录提示（保留现有 pending-actual 流程） |
| 选做 | 切换 `is_optional` | 双向开关，走 `PATCH /api/assignments/{id}/optional` |

"跳过"不再作为独立按钮暴露，而是由"选做"承担语义：家长不想做某项时，标记为选做即可把它移出待完成区。**这解决了原设计"跳过"与"选做"功能重叠的问题。**

### 3.2 进度口径

后端 `build_today_board` 的 `progress` 扩展为：

```json
{
  "done": 3,
  "skipped": 1,
  "settled": 4,
  "total": 5,
  "optional": 2,
  "pct": 80
}
```

- `total` = 全部条目数（含 optional）
- `optional` = 选做数
- `settled` = done + skipped
- `pct` = `settled / (total - optional) * 100`，分母为 0 时取 100

### 3.3 看板分区

```
[进度条 80%]  已收尾 4/5 · 估时 95 分
[提示条] 今日还有 1 项要做

待完成
  [卡片] 作业行 × N

已收尾
  [卡片] 划线作业行 × N

▸ 选做（2）· 有空再做      ← 默认折叠
```

### 3.4 录入页批次级日期

- 解析页新增 `#entry-date` 日期输入框，默认今天
- 预览表每行仍可单独改
- AI 未返回 `due_date` 的行：输入框留空 + 红色高亮 + 行内提示"请确认归属日"，**不再静默填今天**
- 入库时该行未填则阻止提交并聚焦到第一个空行

## 四、视觉设计

### 4.1 配色（奶油糖果）

替换 `:root` 全部颜色变量。无灰底、无纯黑文字。

| 变量 | 值 | 说明 |
|---|---|---|
| `--bg` | `#FFF8F0` | 暖奶油底 |
| `--surface` | `#FFFFFF` | 卡片 |
| `--surface-2` | `#FFF1E4` | 次级底 |
| `--border` | `#FFE0CC` | 描边 |
| `--text-1` | `#4A3728` | 深棕，替代近黑 |
| `--text-2` | `#8A6F5C` | |
| `--text-3` | `#BFA894` | |
| `--c-语` | `#E07A4E` | 实底色 + 白字 |
| `--c-数` | `#3E9CC4` | 实底色 + 白字 |
| `--c-英` | `#5FA055` | 实底色 + 白字 |
| `--status-done` | `#3FA34D` | |
| `--accent` | `#FF6B9D` | 主按钮 |

**科目标签改实底色**：因"复习/听写/默写"这类简称在语数英中高度重复，纯文字标签无法区分，实底色是最低认知成本的区分手段。

### 4.2 形状语言

保持现状：13px 圆角卡片、2px 描边 + 硬阴影、胶囊按钮、圆头进度条、系统字体。

已评估并否决"作业本风格"（装订边 + 横线纸纹 + 手写体 + 直角清单）——用户认为观感别扭。

## 五、同时修复的缺陷

改版过程中发现以下既有缺陷，一并修复：

| 级别 | 缺陷 | 位置 |
|---|---|---|
| P0 | 手动添加空截止时间生成 `":00"` → 入库必失败 4003 | `app.js` 手动提交 |
| P0 | `progress.est_total` 后端从未返回 → 估时永远显示 0 | `app.js` / `assignment_service.py` |
| P0 | 已完成任务删除按钮可见，但后端必拒 4010 | `app.js` |
| P1 | `todayStr()` 用 `toISOString()`（UTC），凌晨时段日期偏移一天 | `app.js` |
| P1 | AI 未识别日期时静默填今天，绕过家长确认 | `app.js` |
| P1 | 选做在看板上零调用（后端接口就绪） | `app.js` |
| P1 | 状态回退不清 `actual_minutes` → 待办任务显示耗时，且污染周复盘 | `assignment_service.py` |
| P1 | `task_type != 'observation'` 在 NULL 时三值逻辑过滤掉记录 | `analytics_service.py` |
| P2 | 跳过态仅靠颜色区分（色盲不可识别） | `styles.css` / `app.js` |
| P2 | 全链路 `alert` 打断流程，已有 toast 基础设施未使用 | `app.js` |
| P2 | 看板全量重建导致滚动跳顶、输入被清空 | `app.js` |
