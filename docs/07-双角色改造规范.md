# 双角色改造规范 (kid / parent)

> 版本：v1.0 · 日期：2026-11-01 · 作者：Mavis (设计主导)
> 配套：`docs/02-页面设计.md`（旧版家长视角，已被本文档取代）、`docs/01-功能设计.md`
> 本文是**前端 CSS / JS 与后端实现共同遵循的契约**。类名、接口、字段名一律以此为准。

---

## 0. 一句话方向

> **同一本作业本，两种读法。**

孩子读的是**方格本 + 星星罐**：一张纸，一格一格往前爬，攒下来的星星装进罐子。
家长读的是**备课本 + 批改台**：一行一行对账，看的是效率与结论。

两端是**同一份数据**、**同一套颜色编码**，但纸不一样、信息密度不一样、能做的操作不一样。

## 1. 角色模型

### 1.1 角色状态

- `document.documentElement.dataset.role` = `"kid"` | `"parent"`
- 持久化：`localStorage["st.role"]`，默认 `"parent"`
- 切换控件：header 右上角 `.role-switch`

### 1.2 家长端 PIN 门槛

| 情况 | 行为 |
|---|---|
| 家长 → 孩子 | 直接切，无需验证 |
| 孩子 → 家长，且已设 PIN | 弹 `.pin-gate`，输对才放行 |
| 孩子 → 家长，且未设 PIN | 弹 `.pin-gate`，提示"首次使用，请先设置 4 位密码"，设置完直接进入 |
| 连续输错 3 次 | 提示"密码错了 N 次"，锁 60 秒（前端计时，不持久化） |

PIN 存后端（PBKDF2 哈希），**前端不存明文 PIN**，只有"是否已设置"走本地标记。

### 1.3 导航

两个角色都是 **3 个 Tab**，但内容不同。

| Tab | 家长端 | 孩子端 |
|---|---|---|
| 今日 | 批改台（数据卡 + 批量操作 + 密集任务行） | 星星罐 + 大任务卡 |
| 日历 | 热力图 + 悬停详情卡 | 贴纸册 |
| 复盘 | 周期复盘（环形图 / 折线 / 薄弱项） | 我的成绩单（勋章墙 + 成长报告） |

**家长端专属页**（不在 Tab 里，从页面内进入）：

| 页面 | 入口 | hash |
|---|---|---|
| 登记作业 | 今日页右上「＋ 登记作业」按钮 | `#/entry` |
| 周计划 | 日历页右上「月历 \| 周计划」分段切换器（周计划页顶上也有同一个，可切回） | `#/week` |
| 设置 | header 右上角头像菜单 | `#/settings` |

孩子端**看不到**登记 / 周计划 / 设置的入口。

### 1.4 路由

沿用现有 hash 路由与 `switchTab()`，新增：

- `#/settings` 已存在
- Tab 键名不变：`board` / `list` / `review`
- 孩子端切到 `entry` / `week` / `settings` 时**回退到 `board`**，不报错

## 2. 色彩系统

### 2.1 共用编码（两个角色完全一致，贯穿看板 / 日历 / 复盘）

每个颜色给两个值：`-c` 主色（文字 / 描边 / 实底）、`-t` 浅底（chip 背景）。
**主色对白底、以及对自身浅底的对比度都必须 ≥ 4.5:1**（实底 chip 上是白字，
浅底 chip 上是主色字，两头都得够）。

| 类别 | 主色 | 浅底 | 主色/白底 | 主色/浅底 |
|---|---|---|---|---|
| 语文 | `--s-yu-c: #BF3B2E` | `--s-yu-t: #FBEAE6` | 5.41 | 4.64 |
| 数学 | `--s-shu-c: #2C6BA8` | `--s-shu-t: #E7F0F8` | 5.56 | 4.82 |
| 英语 | `--s-ying-c: #457315` | `--s-ying-t: #F0F5E4` | 5.65 | 5.08 |
| 培训 | `--s-pei-c: #6B4C9A` | `--s-pei-t: #EEEAF6` | 6.72 | 5.67 |
| 习惯 | `--s-xi-c: #1F7368` | `--s-xi-t: #E4F1EF` | 5.66 | 4.89 |

**状态色**（形状 + 颜色双信号，禁止只靠颜色）：

| 状态 | 主色 | 浅底 | 主色/白底 | 主色/浅底 |
|---|---|---|---|---|
| 待做 | `--st-todo-c: #6E6459` | `--st-todo-t: #F0EDE8` | 5.78 | 4.95 |
| 进行中 | `--st-doing-c: #8F5600` | `--st-doing-t: #FBF0DC` | 6.00 | 5.32 |
| 已完成 | `--st-done-c: #1D7A4C` | `--st-done-t: #E3F2EA` | 5.33 | 4.61 |
| 选做 | `--st-opt-c: #6F6A5F` | `--st-opt-t: #F2F0EC` | 5.38 | 4.73 |
| 逾期 | `--st-late-c: #C2321F` | `--st-late-t: #FBE7E3` | 5.57 | 4.68 |

> ⚠️ **初版这三个值是错的**：英语原为 `#5A8F1E`（3.90）、进行中原为 `#C77700`（3.46）、
> 选做原为 `#8C8578`（3.66），都达不到 4.5:1。本表是复核后的值，
> **改动任何一个都要重算这两列**。
>
> 形状信号：待做 = 空心圆点；进行中 = 实心圆 + 进度条；已完成 = 对勾 + 花贴纸；
> 选做 = 虚线描边 + 「选」字；逾期 = 左红条 + ⚠。

**置信度色**（2026-11-02，AI 读得准不准，与作业状态是两条轴，但沿用同一套色相做交通灯读法）：

| 置信度 | 主色 | 浅底 | 主色/白底 | 主色/浅底 |
|---|---|---|---|---|
| 高 | `--conf-high` → `--st-done-c` | `--conf-high-t` → `--st-done-t` | 5.33 | 4.61 |
| 中 | `--conf-medium` → `--st-doing-c` | `--conf-medium-t` → `--st-doing-t` | 6.00 | 5.32 |
| 低 | `--conf-low` → `--st-late-c` | `--conf-low-t` → `--st-late-t` | 5.57 | 4.68 |

> **不新增色值**：置信度色是状态色板的别名，对比度直接沿用上表，改置信度色
> 不会动到学科色与状态色的验收基线。
>
> **三档必须各有各的颜色**：高置信度原来用中性灰 `--text-3`，在登记页那一列里
> 和普通弱化文字长得一样，家长扫过去读不出置信状态（功能设计 §2.4 第 10 条）。
>
> **颜色是第二信号**：形状（`●` / `◐` / `⚠`）、文字（「高」/「推断」/「需核对」）、
> `title` + `aria-label` 仍是第一信号。
>
> **圆点与标签同色**：登记页预览表用 `.conf-dot`（窄列放不下多字标签），看板行与
> 原文弹窗用 `.confidence-pill`，两者取同一套令牌。

## 3. 字体

| 角色 | 用途 | 字体 | 回退栈 |
|---|---|---|---|
| 孩子端 | 标题 / 任务名 | **系统楷体** | `"Kaiti SC", "STKaiti", KaiTi, "楷体", "LXGW WenKai TC", serif` |
| 家长端 | 标题 | **系统宋体** | `"Songti SC", SimSun, "宋体", "Noto Serif SC", serif` |
| 两端 | 正文 / UI | 系统黑体 | `-apple-system, "PingFang SC", "Microsoft YaHei", sans-serif` |
| 两端 | **所有数字** | 系统黑体 + `tabular-nums` | 不用衬线/楷体渲染数字，保证竖列对齐 |

**刻意不引 Google Fonts CDN。** 本项目是本地部署、要求离线可用
（`tests/test_datepicker.py::test_no_cdn_dependency` 钉着「页面不得直接引用外部 CDN」），
而楷体与宋体在 Windows（`KaiTi` / `SimSun`）与 macOS（`Kaiti SC` / `Songti SC`）都自带，
用系统字体既保住了「孩子用楷体、家长用宋体」的角色区分，又不引入网络依赖、
不必下 20MB 的中文字库、也不会在离线时闪一下系统字体。

字体栈统一定义在 `styles.css` 的 `--font-display`（按 `[data-role]` 覆盖）与 `--font-ui` / `--font-num`。

> ⚠️ 数字**一律**用系统黑体 + `tabular-nums`，**不跟随** display 字体 ——
> 楷体/宋体的西文数字宽度不等，预估 35 分 / 实际 40 分上下排会歪。

## 4. 组件规范

### 4.1 孩子端 · 星星罐（签名组件）

```html
<div class="kid-hero">
  <div class="jar" aria-hidden="true">
    <svg viewBox="0 0 120 140">…玻璃罐 + 星星…</svg>
    <div class="jar-fill" style="--stars: 3"></div>
  </div>
  <div class="kid-hero__text">
    <p class="kid-hero__line">还差 <b>2</b> 项就全部完成啦</p>
    <p class="kid-hero__sub">今天拿到 <b>3</b> 颗星 · 罐里有 <b>18</b> 颗</p>
  </div>
</div>
```

- 罐子高度随 `--stars` 填充比例变化（`--stars / --jar-cap`，容量 20 颗封顶后显示溢出数）
- 每颗星是五角星 path，从罐底往上堆，最多可见 9 颗（超出用 `+N` 角标）
- 星星三色随机取 `--star` / `--star-2` / `--star-3`，但**位置固定**（用 id 派生种子，不用 `Math.random`，避免重绘时星星乱跳）
- 全部完成时罐子加 `.is-full` class，出现溢出的星星 + 庆祝层

### 4.2 孩子端 · 任务卡

```
┌────────────────────────────────────────────────────────┐
│ ▎完成能手 P14                        [完 成] [⏱]  ⋯   │
│   语文 约 20 分钟                                     │
└────────────────────────────────────────────────────────┘
  ↑ 左色条 = 学科色         ↑ 唯一主按钮 48px  ↑ 计时 48×48  ↑ 更多
```

- **单行布局**：任务名在中间靠左，操作按钮靠右排。学科与预计用时是任务名下方的
  一行小字（第二行），不是单独一行。
- 卡片圆角 **14px**，底 `--paper-2`，描边 `--rule`，内边距 `8px / 12px`
- 孩子端**只保留**「完成」一个大按钮；编辑 / 今天不做 / 删除 全部收进最右的 `⋯` 菜单
- 「开始计时」在孩子端是**图标按钮**（沙漏 `#i-clock`，48×48）：卡片是单行的，
  「开始计时」四个字会挤掉任务名的宽度。计时中按钮放开宽度直接显示计时数字。
  家长端仍是文字按钮 + 旁边的计时读数，两边互不影响。
- 「完成」是蜡笔黄填充 + 深墨字，按下时轻微下沉（`transform: translateY(1px)`）
- 完成后卡片变成「已完成」态：左侧色条变绿、卡片降饱和、显示「完成啦 ✓」

> ⚠️ **密度是这一段的重点**（2026-11-01 用户反馈：「项目占用位置太高了，
> 看起来像是待办事项」）。初版把学科行 / 任务名 / 按钮行竖着堆三行，一张卡
> 138px 高，一屏只看得下两三项，视觉上像「大卡片」而不像「待办事项」。
> 压成单行后卡高 **66px**，一屏五六项 —— 孩子自己就能数出还剩几件事。
> 触控目标没缩水：「完成」仍 48px 高，计时器 48×48。

### 4.6 家长端 · 复盘可视化

> **2026-11-02 已被 §4.6.2 取代**：下面这份是 v2.0 的原契约（手写 SVG 环图 + 折线），
> 实现后发现复盘页一度出现 **4 张图却只有 2 份独立数据**。保留原文是为了留痕，
> **当前实现以 §4.6.2 为准**。

- **环形占比图**：科目用时占比，SVG `stroke-dasharray` 画环，中心显示总分钟数
- **每日用时折线**：7 个点，异常高点（超过中位数 1.5 倍）标红并给出原因说明
- **薄弱项卡**：从 `daily_reflections.tags` 聚合出"本周数学错题整理耗时最长"这类结论
- **未完成任务**：每条右侧一个「挪到下周」按钮，一键改 `due_date` 到下周一

**实现补充（2026-11-01 验收后定）**：

| 决定 | 原因 |
|---|---|
| 这三块**放在复盘页最上面**，不是追加在末尾 | 旧的周报块很长（负荷表 / 偏差表 / 口径说明都在里面），追加的话要滚过三屏才看得到。复盘的诉求就是「先看结论再看明细」，环形图就是结论 |
| 折线图**逐点印数值**，不藏在 tooltip 里 | 家长扫一眼要的是"哪天高、多少分钟"。数值印在点上方，另加一条最高点虚线 + 右上角刻度值 |
| 折线说明文字**跟着数据走** | 有异常点就点名（"周三 162 分钟明显高于平时"）；没有就换一句（"最高的一天是周三 162 分钟，这周比较平稳"）。不能写死"标红的点明显高于平时"却一个红点都没有 |
| 新块标题**不叫「各科用时占比」** | 旧周报块里已有一张同名的饼图（预计 vs 实际），两张同名卡片挨着出现会让人以为是同一张图出了 bug。新块叫「学科用时分配」「每日用时趋势」 |

### 4.6.1 家长端 · 日历悬停详情卡

家长端日历格子 hover 弹一张浮层卡（`.cal-tip`，`position: fixed`），四行：

| 行 | 内容 | 来源 |
|---|---|---|
| 完成率 | 百分比 | `/assignments/calendar` 当天 `required_done / required` |
| 总用时 | 分钟 | 同上 `actual_total` |
| 各科用时 | 学科色圆点 + 科目 + 分钟 | 按天取作业，累加**已完成**条目的实耗（无实耗用预估） |
| 课外班 | 名称 + 时间段 | `/week-plan` 当天的 `slots`（`project_name` / `start_time` / `end_time`） |

三条硬要求：

1. **`.cal-tip` 必须在 `styles.css` 里有规则** —— DOM 里建了不等于界面上看得见。
   卡片 `position: fixed`（`getBoundingClientRect()` 是视口坐标）；`pointer-events: none`（否则指针移到卡上会触发格子的 `mouseout`，卡自己先消失）。
2. **定位要夹在视口内** —— 优先落在格子下方，下方放不下就翻到上方。
   各科用时/课外班是异步回来的，卡的高度会变，**回填后要重新定位一次**。
3. **孩子端不弹这张卡** —— 那边是贴纸册，靠点格子看详情。

### 4.6.2 家长端 · 复盘可视化（**当前契约**，2026-11-02）

**两张图，不多不少：**

| # | 图 | 形式 | 回答什么 |
|---|---|---|---|
| 1 | **每日作业用时** | ECharts 堆叠柱状图，按科目分色 | 哪天高、哪科占得多 |
| 2 | **各科时间占比** | ECharts 环图，**一个环 + 预估/实际切换** | 时间都花在哪科 |

**为什么不是 v2.0 的那套**：

| v2.0 写法 | 实测问题 | v2.1 决定 |
|---|---|---|
| 环形占比图（SVG `stroke-dasharray`） | 与旧周报块里的「实际占比」饼图**数据完全相同**，两张同名卡挨着 → 被当成同一张图出了 bug | 删掉手写环，改为 ECharts，**预估/实际合成一个环 + 切换** |
| 每日用时折线（`days.slice(-7)`） | 折线数据 = 柱状图数据；标题写死「最近 7 天」但实际取的是区间末尾 7 天 | 折线**整体删除**，其「异常高点」语义由柱状图角标 + 说明文字承接 |
| 手写 SVG 坐标 | 月视图三十来天挤一屏，标签互相压字 | 换 ECharts：内置 `labelLayout.hideOverlap` + `dataZoom` |

**硬约束**

1. **复盘页最多两张图** —— 多于两张家长要自己判断哪张是真的。
2. **柱状图合计 === 环图合计 === 月报合计** —— 三个数摆在同一页，对不上就等于告诉家长图画错了。
3. **「显示周末」开关两张图一起生效** —— 藏一半（柱藏环不藏）比不藏更糟。
   实现上：后端给**逐日** `by_subject` 与 `est_by_subject`，前端用
   `charts.js:shareOfDays()` 按**看得见的那几天**重算占比。
   后端的整段 `subject_share` 口径**不动**（它仍统计含周末的整段）。
4. **预估与实际共用一个环**，切换用 `setOption(option, true)` 复用实例（重建会闪，且容易漏 dispose）。
5. **整段零用时不画图** —— 只留空态文案。
6. **图表层独立成 `app/static/charts.js`** —— option 构造是纯函数，能在 node 里直接测。
7. **没有 canvas 时降级成 HTML 表格**（jsdom / 老浏览器不白屏）。
8. **换周期 / 切走复盘页时 dispose 实例** —— 只摘 DOM 不 dispose 会泄漏实例。
9. **ECharts 必须本地 vendor**（`app/static/vendor/echarts.min.js`）——
   禁止 CDN 是硬红线（见 `docs/08` §2.5）。
10. **画布不认 CSS 变量** —— 运行时 `resolveCssColor()` 解析 `var(--c-语)`，
    `charts.js` 里**不另建**一份「科目→色」表（`app.js:SUBJECT_COLORS` 是唯一来源）。

**月统计（2026-11-02 新增）**

「本月」周期额外给：月报卡（合计 / 完成率 / 与**上月同期**比）+ 月内按周对比图。
环比用**上月同期对齐**（本月过 2 天就只比上月 1–2 日），否则月初永远显示「少用了 95%」。

### 4.7 晚间小结（家长端专用，轻量化）

- 难度 / 专注 / 情绪 → **大色块按钮**（不是小 chip），选中态实心填充 + 对勾
- 文字备注 → 改成**标签快选**（点选即用，多选）：
  `写字慢` `读题走神` `错题多` `内容不熟` `速度正好` `很专心`
- 「保存」按钮固定在模块底部，永远可见可点
- 标签通过 `daily_reflections.tags` 落库（新增列，见 §5.3）

### 5.3 自动发星 / 撤销

在 `assignment_service.update_status()` 与 `update_completion()` 里挂钩：

| 事件 | 星星 | reason |
|---|---|---|
| 状态 → `done`（必做 / 选做 / 训练 / 习惯都算） | +1 | `earn_task` |
| 状态从 `done` 退回其他 | −1（撤销该 assignment 的星） | `revoke_task` |
| 当天全部必做完成 | +3 | `bonus_all_done` |
| 家长手动奖励 | 任意正数 | `bonus_manual` |
| 家长手动扣除 | 负数 | `spend` |

**幂等**：`idx_star_ledger_assignment_once` 保证同一条作业只发一次星；
撤销时按 `assignment_id` 删掉那一行。

**撤销的口径统一是「删掉那一行」，不是补一行负数** —— 负数行会永久留在账本里，
孩子端看到"完成作业 −1 星"会以为自己的星星被偷了。

**条件奖励也要能回收**（2026-11-01 补）：`bonus_all_done` 是**条件奖** ——
条件（当天必做全完成）不成立了，那 3 颗星必须一起收回来。家长撤销一条完成、
或把一条改成选做/不做，当天就不再全勤，账本里那一行要删掉。
（初版只回收单条作业的星，全勤奖会永久留下，等于孩子白拿 3 颗。）

**升级前的已完成作业不补发星星**：发星挂在 `status → done` 这个**状态变化**上，
不是"扫一遍历史"。所以孩子端上线第一天，罐子里是空的（历史作业都是上线前
就做完的），从这一刻起完成的作业才开始攒星。这是刻意的 ——
补发的话要一次性给几百颗，星星就通货膨胀了，而且"今天又没做什么却多了 200 颗"
会让孩子觉得星星不是自己挣的。

### 5.4 连续天数

当天全部必做完成 → `kid_streaks` 当日行 `current_streak = 上一条 + 1`，
`best_streak = max(best, current)`。当天没全部完成 → 当日行 `current_streak = 0`。

### 5.5 勋章规则

在 `GET /api/kid/medals` 调用时评估，命中就写 `kid_medals`（幂等，UNIQUE 约束兜底）。

| key | 名称 | 条件 |
|---|---|---|
| `first_star` | 启程星 | 累计获得第 1 颗星 |
| `streak_3` | 连续三天 | 连续完成 3 天 |
| `streak_7` | 坚持一周 | 连续完成 7 天 |
| `full_week` | 完美一周 | 一周 7 天全部完成必做 |
| `speedster` | 效率小达人 | 一周完成 ≥5 项，实际用时比预估少 ≥20% |
| `focused` | 专心小蜜蜂 | 一周小结专注度全为 `good`（≥3 条） |
| `tag_master` | 错题克星 | 一周小结里 `many_errors` 标签 ≤1 次且完成率 ≥80% |

勋章条目要有 `name` / `desc` / `icon`（图标用**内联 SVG path 名**，不是 emoji）。

### 5.6 晚间小结标签

`daily_reflections.tags` 存 code，逗号分隔。允许的 code：

```
slow_writing  写字慢      reread      读题走神
many_errors   错题多      unfamiliar  内容不熟
good_pace     速度正好    focused     很专心
```

`POST /api/daily-wrap` 与 `GET /api/daily-wrap` 的 DTO 增加 `tags: list[str]`。

## 6. 文案口径

### 6.1 孩子端词表（禁止出现成人术语）

| 家长端术语 | 孩子端说法 |
|---|---|
| 已收尾 | 已完成 |
| 必做 | 必须完成 |
| 选做 | 有空再做 |
| 已逾期 | 逾期啦 |
| 复盘 | 我的成绩单 |
| 训练打卡 | 练习打卡 |
| 预计用时 | 约 X 分钟 |
| 逾期 | 快点做完呀 |

鼓励语（按剩余项数选一条，轮换避免重复）：

| 剩余 | 文案 |
|---|---|
| 0 | 今天的作业全部完成啦！ |
| 1-2 | 还差 N 项就全部完成啦 |
| 3-5 | 今天作业有点多哦，慢慢来 |
| ≥6 | 今天有点多，先做最想先做的那项 |

#### 历史日期口径（2026-11-03）

看板能翻「昨天」「前天」。那时文案里的「今天」两个字一律换成「这天」
（实现：`kidDayWord(isToday)`，`isToday` 由后端的 `board.is_today` 决定）——
对着昨天的作业喊"今天"，孩子会以为根本没翻页。

同一条规则覆盖孩子端全部与日期相关的显示：

| 位置 | 今天 | 历史日期 |
|---|---|---|
| 鼓励语 | 今天的作业全部完成啦！ | 这天的作业全部完成啦！ |
| 星星数 / 罐子 | 取 `/kid/stars`（今天） | 取 `/kid/stars?date=那天`（那天拿到的星星） |
| 连续天数 | 截止今天 | 截止那天 |
| 空状态 | 今天没有作业，好好休息一下 | 这天没有作业 |
| 任务卡「今天不做」 | 今天不做 | 这天不做 |
| 庆祝层 | 可弹 | **不弹** |

庆祝层另有一条：**一个日期只弹一次**，记录写浏览器
`localStorage["st.kid.celebrate"]`（内存只兜本次会话，刷新后靠 localStorage 记住）。

### 6.2 家长端词表

保留专业术语，但**每个数据都补一句直白结论**：

> 本周作业用时 520 分钟，比上周少 245 分钟，效率提升了。

## 7. 交互细则

### 7.1 完成反馈

| 场景 | 反馈 |
|---|---|
| 单项完成（孩子端） | 星星从卡片飞进罐子（260ms，`transform` + `opacity`），卡片翻成「完成啦 ✓」 |
| 单项完成（家长端） | 行内变绿 + 对勾，无动效 |
| 当天全部完成 | 全屏 `.celebrate` 庆祝层：星星从上方落下 + 「今天全部完成啦！」+ 获得 3 星提示 |
| 撤销完成 | 星星从罐子里退掉，无庆祝 |

`.celebrate` 尊重 `prefers-reduced-motion: reduce` → 关闭落星动画，只留静态文案。

### 7.2 计时器

- 任务卡上的「开始计时」按钮 → 计时中显示 `已计 12:34`，再点一次停止
- 停止后把实际用时（分钟，四舍五入，最少 1）写进 `actual_minutes`
- 计时状态存内存（刷新丢失），不要持久化

### 7.3 批量操作（家长端）

选中 ≥1 条时 `.p-batch-bar` 出现，支持：

| 操作 | 实现 |
|---|---|
| 设为选做 | 循环 `PATCH /api/assignments/{id}/optional {is_optional:true}` |
| 取消选做 | 同上，`false` |
| 改到明天 | 循环 `PATCH /api/assignments/{id} {due_date: 明天}` |
| 删除 | 循环 `DELETE /api/assignments/{id}`，**必须二次确认** |

批量操作全部走**已有接口**，不新增后端端点。

### 7.4 键盘与无障碍

- 所有交互元素键盘可达，`:focus-visible` 有 2px 描边
- 状态不只靠颜色：形状 + 文字双信号
- 触控目标：孩子端 ≥48×48px，家长端 ≥40×40px
- `prefers-reduced-motion: reduce` 下关闭所有动效
- 贴纸 / 勋章的 `<svg>` 必须有 `aria-hidden="true"` + 相邻的 `aria-label` 文字
